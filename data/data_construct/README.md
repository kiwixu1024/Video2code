# Video2Code data construction

This directory explores interactive HTML pages or URLs, records successful
interactions, and produces the videos and timeline JSON consumed by the data
processing pipeline.

## Pipeline

```text
HTML files / URL list
        |
        v
00_collect_interactions.py
        |-- launches webenv-init/webenv.py
        |-- asks a vision model to select interactions
        |-- executes and validates each interaction
        `-- retains only the filtered video
        |
        v
output/
|-- results/<id>.json
`-- videos/<id>.mp4
        |
        v
../data_process/01_build_timeline_dataset.py
```

The saved MP4 is the filtered version generated by `merge_video_longest`. Its
timestamps correspond to `action_frames_timeline_filtered` in the JSON file.
There is no unfiltered video or `<id>_filtered.mp4` duplicate.

## Directory layout

| Path | Purpose |
|---|---|
| `00_collect_interactions.py` | Main construction entry point |
| `agent_tools/config.py` | CLI, JSON, and environment configuration |
| `agent_tools/helpers.py` | Browser exploration helpers |
| `agent_tools/video_edit_tools.py` | Video merging and timeline extraction |
| `webenv-init/webenv.py` | Local browser interaction service |
| `webenv-init/*.png` | Cursor assets used in recorded videos |
| `legacy_tools/` | Archived one-off dataset utilities; not part of the pipeline |
| `config.*.example.json` | Safe example configurations |

Files under `webenv-init/old_versions/` are historical references and are not
used by the published pipeline. The same applies to `legacy_tools/`; those scripts
retain experiment-specific defaults and are provided only for provenance.

## Installation

From the repository root:

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
playwright install chromium
cp data/data_construct/.env.example data/data_construct/.env
```

Export the values from `.env` in the current shell. The program deliberately does
not read secrets from version-controlled JSON files.

## HTML mode

Copy the example and edit its input/output paths:

```bash
cp data/data_construct/config.html.example.json data/data_construct/config.local.json
export OPENAI_API_KEY=your-key
python data/data_construct/00_collect_interactions.py \
  --config data/data_construct/config.local.json
```

## URL mode

The URL file accepts one URL per line. JSONL records containing a URL are also
supported by the existing loader.

```bash
cp data/data_construct/config.url.example.json data/data_construct/config.local.json
export OPENAI_API_KEY=your-key
python data/data_construct/00_collect_interactions.py \
  --config data/data_construct/config.local.json
```

Relative paths in a JSON configuration are resolved relative to that JSON file.
Command-line values override environment variables, which override JSON values.
Available environment variables are listed in `.env.example`.

## Connect to data processing

Set the construction output and processing root to the same directory:

```bash
export VIDEO2CODE_DATA_ROOT=/absolute/path/to/output
python data/data_process/01_build_timeline_dataset.py
```

Step `00_normalize_filtered_videos.py` is unnecessary for newly constructed data,
because construction now writes the filtered video directly to `videos/<id>.mp4`.

## Operational notes

- FFmpeg and ffprobe must be installed and available on `PATH`.
- Each worker uses a local TCP port beginning at `port_base`.
- Start with four workers and increase only after checking model rate limits and
  local CPU/memory usage.
- Existing result JSON files are treated as completed and skipped on reruns.
- Never commit `.env`, API credentials, generated videos, or exploration output.
